Machine Learning
from scratch

Ninety minutes to understand what a computer actually does when it "learns". No heavy math, nothing to install. You will poke, guess and get it wrong before you see the answer.

Every block opens with a question. Think about it (or vote in the chat) before you open the Reveal panel. Getting it wrong first is the whole point.
Block 1

The problem that will not fit into rules

Three messages just landed in your inbox. Two are real, one is a scam.

A CONGRATULATIONS!!! You have won a FREE iPhone, click here
B Hi, your card statement is ready, it is available at the link
C Free entry to Saturday's show, want to come? Let me know
Write a one-line rule that separates spam from not-spam.
Reveal

Every rule has a counter-example sitting right there. "Contains free"? Message C is from your friend. "Has a link"? B is from your bank. "All caps"? What about that urgent email from work?

You just did what engineers did for thirty years: write the rules by hand. And you found out why it fails: the world has more cases than any list can cover.

Machine learning flips that logic around. Instead of writing the rule, we hand over examples and let the computer find the rule on its own. The rest of this class turns that sentence into something precise.

Reveal

Only the music app and the camera learn. The test is a precise one:

A system learns when its performance at a task improves with experience. Tom Mitchell, 1997

Today's thermostat is identical to yesterday's, no matter how many winters go by. Today's music app suggests different tracks than it did a month ago because it saw more data.

IngredientMusic appSpam filter
Task (what it does)suggest the next trackseparate spam
Experience (what it sees)tracks played and skippedemails users already flagged
Performance (how we measure)how many suggestions you listened to all the way% of emails filed correctly

Any time you get lost in this class, the rescue question is: "is this the task, the experience or the performance?"

Block 3

Is there an answer key or not?

A farmers' market. Someone weighed and tasted 60 pieces of fruit and wrote down two things about each: weight and sweetness. Every dot below is one piece of fruit.

Looking only at the grey dots, what can you figure out? And what changes when we switch the labels on?
orangeapple
Reveal

Without labels you can still see something: the dots fall into two clumps. You can say "there seem to be two kinds of fruit here", but you cannot say which. That is unsupervised learning: finding hidden structure with no answer key.

With labels, the problem changes character. Now we can learn the relationship between the measurements and the name, and predict the label of a new piece of fruit. That is supervised learning: the data comes with the right answer attached.

Answer key?TaskExamples
Supervisedyeslearn input → answerspam, diagnosis, price forecasting, speech recognition
Unsupervisednofind groups and patternscustomer segments, unusual fraud, grouping news stories

There is a third family, reinforcement learning (learning by trial and reward, as in games and robotics). This class stays in supervised learning, where most everyday applications live.

One piece is missing. The fruit already arrived as numbers — weight and sweetness — but the three messages in block 1 were plain text. How would a model look at them? Like this:

Message# of "!"has a linkwords in capsspam?
A FREE iPhone302yes
B card statement010no
C Saturday's show000no

Every message became a row of three numbers plus the label, exactly the shape of the fruit table. All data has to become numbers before any model; this is called representation. Deciding which numbers to pull out is half the work, and it is a human decision: notice that the table above already threw away who sent the message, the time of day, the language.

And a warning that holds for the rest of the class: a model learns what the examples show, including the mistakes of whoever labeled them. If the person who flagged the emails mixed up promotions with scams, the model will mix them up too.

Reveal

The input is identical. What changes is the type of output:

(a) a continuous number → regression · (b) one category out of a few → classification

The distinction lives entirely in the output. It is not that "regression is more mathematical", nor that "regression takes numbers as input". There is only one question: is the answer a label or a quantity?

Block 5

A model is a formula with blanks in it

Let us stay with regression for a moment, because it shows the most important idea of the class stripped bare. Below, 12 apartments from the same neighborhood: floor area on the horizontal axis, price on the vertical one.

Draw a line that "explains" these points. Which two numbers do you have to choose?
price = a × area + b
Total error (sum of the red bars): —
The same thing, in Python

The two sliders you moved are these two numbers. There is no button here: fit runs the same search that "let the computer learn" ran.

from sklearn.linear_model import LinearRegression

X = [[45], [52], [60], [68]]   # the floor area of each apartment
y = [310, 360, 395, 440]       # the price of each one

model = LinearRegression()
model.fit(X, y)                # searches for the best a and the best b

print(model.coef_[0])          # the "a" slider: the slope
print(model.intercept_)        # the "b" slider: the starting point
Reveal

You picked two numbers, a and b. While you moved them around you were trying to shrink the red bars: the gap between what the line predicts and what actually happened. That is exactly what a computer does when it "learns", only much faster and for thousands of numbers at once.

A model is a formula with blanks in it. Learning is filling those blanks with the numbers that make the error smallest.

This takes apart a common confusion: the computer does not "understand" apartments. It tunes numbers in a formula until the formula imitates the examples. The more examples, the better the fit. When the "let the computer learn" button moved the sliders by itself, that is all it was doing: searching for the best a and b.

The technical names, so you recognize them later: the blanks are the parameters; the red bars added up are the loss function; the automatic tuning is training.

Block 6

A model with no formula: nearest neighbors

Back to the fruit, labels switched on this time. A new piece of fruit arrives that nobody has tasted. All we know is its weight and its sweetness.

You know no formula at all. How do you guess apple or orange? Tap the chart to drop the new fruit in.
orangeapplenew fruit
Tap the chart.
The same thing, in Python

The fruit you dropped on the chart is the new_fruit line, and the k slider is n_neighbors.

from sklearn.neighbors import KNeighborsClassifier

X = [[150, 0.62], [205, 0.40], [148, 0.66]]   # weight and sweetness
y = ["apple", "orange", "apple"]              # the label of each one

model = KNeighborsClassifier(n_neighbors=3)   # the k from the slider
model.fit(X, y)                               # here, learning = storing

new_fruit = [[170, 0.55]]                     # the one you put on the chart
print(model.predict(new_fruit))               # the label that won the vote
Reveal

You probably thought: "I look at the similar fruit around it". That has a name: k nearest neighbors (k-NN). To classify a new piece of fruit: measure its distance to every known one, take the k closest, and let the label win by vote.

Notice there is no formula with blanks here. The model simply stores the examples. And it is still ML: with more tasted fruit, the vote gets more reliable. So "model" is a broad word: sometimes it is a fitted formula, sometimes it is an organized memory. What they all share is that they turn past examples into predictions about new cases.

The decision map paints what the model would answer at every point of the chart. Notice how at k = 1 it is full of strange islands around isolated fruit, and how the borders smooth out as k grows. Hold on to that picture for the next block.

Block 7

The 100% trap

Let us grade the model. We take the 60 known pieces of fruit, ask the k-NN for the label of each one, and count the hits.

With k = 1, what score does the model get on fruit it already knows? Can we ship that model to the market?
fruit the model saw (training)hidden fruit (test)
The same thing, in Python

The hidden-fruit slider is test_size, and the two bars on the chart are these two scores.

from sklearn.model_selection import train_test_split

# hide 30% of the fruit before training
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=7)

model = KNeighborsClassifier(n_neighbors=1)
model.fit(X_train, y_train)          # only ever sees the training fruit

print(model.score(X_train, y_train)) # dark bar: on what it saw
print(model.score(X_test, y_test))   # purple bar: on the hidden fruit
Reveal

With k = 1 and 0% hidden, the score is 100%. And it is a lie. When we ask about a fruit that is already in memory, its nearest neighbor is itself. The model predicted nothing: it memorized.

Grading on the same data you learned from is marking an exam whose answer key the student already read. Hence the central idea of the whole field:

The goal of a model is not to get the examples it has seen right. It is to get right the ones it has not seen yet. That is called generalization. A model that only gets the training set right is memorizing, and the technical name is overfitting.

The fix is honest and simple: hide part of the data before training and only look at the score there. Move the hidden-fruit slider: the training score stays high while the test score tells the truth. Then move k: with a small k the model memorizes (100% on training, lower on test); with a huge k it always answers whichever fruit is most common (both scores drop). The middle is usually best. k is a number we pick before training, a hyperparameter; a good share of practical ML work is turning knobs like this one and measuring.

The code that drew this figure

It is the same fit from block 6. All that changed is asking for the answer at thousands of points at once, so we can paint the background.

import matplotlib
matplotlib.use("Agg")          # draw into memory, not into a window
import io, base64
import numpy as np
import matplotlib.pyplot as plt
from matplotlib.colors import ListedColormap
from sklearn.datasets import load_iris
from sklearn.neighbors import KNeighborsClassifier

iris = load_iris()
X = iris.data[:, 2:4]          # just 2 measurements: petal length and width
y = iris.target                # 0 setosa, 1 versicolor, 2 virginica

model = KNeighborsClassifier(n_neighbors=k)    # k comes from the slider above
model.fit(X, y)                                # the same fit as block 6

# ask the model for its answer at EVERY point of the plane: that is the map
gx, gy = np.meshgrid(np.arange(0.5, 7.6, 0.02), np.arange(-0.2, 3.0, 0.02))
Z = model.predict(np.c_[gx.ravel(), gy.ravel()]).reshape(gx.shape)

colors = ["#FF6B57", "#1BA39C", "#7B61FF"]
plt.rcParams.update({"font.size": 12})
fig, ax = plt.subplots(figsize=(6.4, 4.3))
ax.pcolormesh(gx, gy, Z, cmap=ListedColormap(colors), alpha=0.18, shading="auto")
for i, name in enumerate(iris.target_names):
    ax.scatter(X[y == i, 0], X[y == i, 1], c=colors[i], s=38,
               edgecolor="white", linewidth=0.8, label=name)
ax.set_xlabel("petal length (cm)")
ax.set_ylabel("petal width (cm)")
ax.legend(loc="upper left", frameon=False)

buf = io.BytesIO()                                  # a file that only exists in memory
fig.savefig(buf, format="png", dpi=140, bbox_inches="tight")

b) A decision tree

This is the model that boils the examples down to readable rules — the third question left open in block 9. Read it top to bottom: every box is one question about one measurement, and its color tells you which answer wins inside it. Turn the depth up and watch the model trade one coarse rule for several fine ones.

The code that drew this figure

It is the same fit as always — we only swapped KNeighborsClassifier for DecisionTreeClassifier. max_depth is the knob you just turned.

import matplotlib
matplotlib.use("Agg")
import io, base64
import matplotlib.pyplot as plt
from matplotlib.colors import to_rgba
from sklearn.datasets import load_iris
from sklearn.tree import DecisionTreeClassifier, plot_tree

iris = load_iris()
names = ["sepal length (cm)", "sepal width (cm)",
         "petal length (cm)", "petal width (cm)"]

tree = DecisionTreeClassifier(max_depth=d, random_state=0)   # d comes from the slider
tree.fit(iris.data, iris.target)            # the same fit as the earlier blocks

fig, ax = plt.subplots(figsize=(min(4 + 2.6 * d, 13), 2.2 + 1.35 * d))
drawn = plot_tree(tree, feature_names=names, class_names=list(iris.target_names),
                  filled=True, rounded=True, impurity=False,
                  fontsize=max(10, 13 - d), ax=ax)
# plot_tree also hands back the "True"/"False" arrow labels, which are not boxes
boxes = [c for c in drawn if c.get_bbox_patch() is not None]

# paint each box in the page colors: the purer the box, the stronger the color
colors = ["#FF6B57", "#1BA39C", "#7B61FF"]
for box, counts in zip(boxes, tree.tree_.value):
    winner = counts[0].argmax()                          # which class wins in this box
    purity = (counts[0].max() / counts[0].sum() - 1 / 3) * 1.5   # 0 mixed, 1 pure
    box.get_bbox_patch().set_facecolor(to_rgba(colors[winner], 0.12 + 0.8 * purity))
    box.get_bbox_patch().set_edgecolor("#17203A")

buf = io.BytesIO()
fig.savefig(buf, format="png", dpi=120, bbox_inches="tight")
base64.b64encode(buf.getvalue()).decode()

Books and courses

  • Tom Mitchell, Machine Learning (1997) The definition we used in block 2 — task, experience, performance — is the first page of this book. It has aged remarkably well because it defines the problem rather than whatever was fashionable at the time.
  • An Introduction to Statistical Learning — James, Witten, Hastie and Tibshirani The PDF is free on the official site. Read chapter 2 (what learning means, and why training and test are different) and chapter 3 (the line from block 5, now done rigorously).
  • Google Machine Learning Crash Course A free course with exercises that run in the browser. It is the shortest path between this class and writing your first model on your own.

scikit-learn documentation

  • Nearest Neighbors All of block 6, with the choices that did not fit into the class: how to measure distance, how to weight closer neighbors more, and what to do when the vote ties.
  • Cross-validation The answer to the first question left open in block 9: how to choose k without cheating by peeking at the test score.
  • train_test_split The exact function from block 7. Worth reading what the three parameters that matter do: test_size, random_state and stratify.
  • Decision Trees The tree drawn in block 8, and why it is the easiest model to show to people outside the field: you can read its rules out loud.
